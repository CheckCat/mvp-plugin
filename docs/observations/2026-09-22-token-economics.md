# Экономика токенов пайплайна: вердикт состязательной дискуссии

Дата: 2026-09-22. Метод: 4 дискутанта с конкурирующими гипотезами → перекрёстная
критика → 3 независимых скептика (мандат — рефутация) → защита авторов →
финальный арбитраж. Каждое число ниже воспроизведено минимум двумя независимыми
реализациями. Полный след (позиции, критики, вердикты, скрипты, датасеты) — в
`2026-09-22-token-economics-debate/`; финальная бумага — `final-verdict.md` там же.

Данные: журналы прогонов vireo (1.38 млрд токенов), glotok (568 млн), trellis
(815 млн); опорный прогон mvp:build — `wf_4d14cdc2` (8 задач, 110 агентов,
72.81 млн). Правило подсчёта: дедуп по (файл, requestId), максимум по полю —
наивная сумма завышает в ~2×.

## Куда уходят токены (каноническое разложение)

| статья | wf-прогон | корпус |
|---|---:|---:|
| перечитывание наросшего контекста | 62.8% | 75.0% |
| перечитывание входного префикса | 28.4% | 20.1% |
| первая запись нового (билеты + рост) | 5.5% | ~3.0% |
| output | 1.1% | 0.6% |

Контекст агента растёт линейно (`ctx(k) ≈ 58k + 1432·k`, R²=0.987), суммарный
расход — квадратичен по ходам. 8% агентов держат 68% токенов. Число диспатчей
стоимость НЕ объясняет (r=0.148): форма лестницы задаёт уровень, дисперсию
(11.3× при идентичной лестнице) задаёт задача.

Доли ролей в текущей конфигурации (`REVIEW_SAMPLES=3`, с 372df30 / 2026-08-26):
implementer ≈53%, ревью-контур 31.5–35.7%. Внимание при сравнении с историей:
82% корпуса — отменённая 1-опросная конфигурация (там ревью 17.4%).

## Сложность задачи и цена (вопрос «влияют ли бизнес-связи»)

- Связность как рёбра DAG (`depends_on`) — НЕ влияет: R²=0.034, немонотонно.
- Ширина фронта влияет: files ≥5 против ≤3 = 2.14× по стоимости.
- Ходы на задачу — архитектурный инвариант (134 vs 141 при 4× разнице диспатчей).
- План объясняет 26–44% дисперсии; предиктор дорогих задач из плана переобучен
  (R² 0.405 in-sample → 0.13 LOO) — адресная оптимизация по плану REFUTED.

## Смета механизмов (CONFIRMED)

| Tier | механизм | экономия прогона / wf-корпуса | статус |
|---|---|---:|---|
| 1 | узкие agentType для reviewer/relay + склейка relay-шагов + диета префикса (B-M1/M2/M3) | −13.1% / −10.0% | реализуем сейчас, ни одного неизмеренного параметра |
| 2 | + `maxTurns:15` ревьюерам (фронтматтер роли; существует только поверх Tier 1) + ветка «обрыв ≠ отказ» в workflow.mjs | −17.9% / −15.7% | реализуем сейчас; длинные опросы находок не дают (r=−0.312, все находки ≤15 ходов) |

В деньгах стек даёт примерно вдвое меньше (−18.7%/−19.3%): CAP снимает
в основном cache-read по 0.1× цены; по деньгам Tier 1 сильнее CAP.

Вне сметы плагина (harness-уровень, решение оператора):
`autoCompactWindow: 150000` в settings.json ≈ −29.4% всего корпуса — больше
всех плагинных механизмов вместе. Чистка контекста как механизм ПЛАГИНА = 0%
(инструмента нет) — закрыто согласием всех сторон.

## Кладбище (проверено и убито — не переизобретать)

| механизм | причина смерти |
|---|---|
| «3 опроса ревью → 1» | на исторических данных пропускает реальный баг (89.7%→86.6% catch) |
| мягкий self-cap («остановись и запиши handoff») | базовая частота добровольной остановки 0.5%; строго доминируется жёстким break при p<80% |
| адресный CAP по предсказанию плана | предиктор переобучен; плоский CAP и так самоприцелен (8% агентов = 68% токенов) |
| чистка/компакция контекста из плагина | инструмента нет; 89.6% эффекта — harness |
| слияние агентов ради экономии билетов | квадратика: 2×20 ходов → 1×40 стоит +32% |
| «SDD дороже пайплайна на задачу» | выборка загрязнена (в т.ч. агентами самой дискуссии), при разбросе 53× сравнение 8 vs 8 задач ничтожно |
| deps как мера сложности | R²=0.034 |
| «билет из кеша соседа» как ролевая экономия | кеш-блок 17 236 токенов побайтово одинаков у всех ролей — это харнесс-префикс |

## Систематическая слабость и что с ней делать

Все оценки — контрфактические (реплей прошлых прогонов, не применение).
Поведенческий отклик агентов на потолки реплей не предсказывает. Поэтому
незакрытые вопросы оформлены как проверяемые гипотезы с порогами — см.
реестр `docs/experiments/registry.json` (механизм self-verification, вводится
отдельной правкой). Две обязательные проверки перед сдачей Tier 3:
1. Сохранность работы за швом: сегменты не тратят суммарно более +53% ходов
   сверх несегментированного базлайна (порог безубыточности).
2. Фактическая экономия Tier 1/2 на живом прогоне сходится с реплеем ±30%.
