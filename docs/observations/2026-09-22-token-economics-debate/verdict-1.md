### Статья 1b «билет из кеша соседа» — счёт CONFIRMED, **имя и вывод REFUTED**

Как срез партиции она корректна: билет физически лежит в начале префикса, поэтому
`cr₁` — это буквально та его часть, что пришла из чужого кеша. Спорить не с чем.

Но C пишет: *«билет, который агент прочитал из кеша, оставленного **соседним агентом той
же роли**»* и выводит отсюда против B: *«500 агентов заплатят не 500 записей, а 1 запись
+ 499 чтений»*. Прямой скан первого хода всех 110 агентов ломает оба утверждения:

```
точные значения cache_read на ходу 1:  17 236 -> 55 агентов
                                            0 -> 28
                                       32 327 -> 16
                                       22 337 ->  6 ; 11 291 -> 3 ; 6 164 -> 2
```

- Блок **17 236 токенов совпадает по-байтово** у ролей `reviewer`, `review`-релеев
  **и `validate`**. Один и тот же блок читают агенты разных ролей → это общий
  харнесс-префикс (system + каталог инструментов), **а не ролевой билет**.
  Ролевую часть — медиана 6.8 k сверх префикса — пишет заново почти каждый агент.
- Арифметика «1 запись + N чтений» не наблюдается: на 110 агентов первый ход
  **записал 1.109 M и прочитал 1.645 M**, то есть **40 % токенов билета оплачены
  записью**, ~10.1 k на агента в среднем. Не «одна запись на роль».

**Вердикт: 2.26 % — CONFIRMED как число; трактовка «prompt caching амортизирует ролевой
билет между агентами» — REFUTED.** Амортизируется харнесс-префикс, к которому ни B, ни
кто-либо из плагина отношения не имеет. Контраргумент C против B этой статьёй не держится.
