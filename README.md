# mvp-plugin

Claude Code plugin: пайплайн «от сырого описания идеи до работающего MVP».

## Цепочка скиллов

mvp:brief → mvp:clarify → mvp:bootstrap → mvp:plan → mvp:build → mvp:retro
Сервисный: `mvp:resume` — восстановление контекста после обрыва сессии.

## Iron Law

> LLM думает — скрипты двигают данные. Операция с однозначно правильным
> результатом = скрипт с exit-code, не инструкция модели.

## Продолжение готового проекта (brownfield)

Цепочка выше — greenfield: она проходится один раз. После `mvp:retro`
проект живёт как обычный репозиторий, но доработку по-прежнему можно
провести пайплайном, не переигрывая `brief`/`clarify`/`bootstrap`/`plan`.

Новый цикл (эпоха) — три команды, ни одного нового скилла:

```bash
# 1. открыть завершённый план: epoch+1, аудит-запись, phase -> plan-done
node lib/plan-io.mjs reopen \
  --reason "перевод интерфейса на русский" \
  --invariant "User-facing текст — русский; идентификаторы кода — английские"

# 2. добавить задачи эпохи ОДНОЙ транзакцией (массив в файле)
node lib/plan-io.mjs add-task --json-file tasks-epoch-2.json

# 3. закоммитить состояние и строить
bash lib/finalize.sh plan
#    затем mvp:build — в НОВОЙ сессии, если плагин переустанавливался
```

Инварианты цикла:

- **Готовые задачи неприкосновенны.** `reopen` не сбрасывает ни одного
  статуса: выполненная задача — это коммит, её `sha` уже в `ledger.md`.
  Продолжение идёт только через добавление задач.
- **`--reason` обязателен.** Команда заменяет собой ручной
  `state.sh set phase plan-done` — правку состояния без предусловия и без
  следа. Причина продолжения хранится в `plan.reopened[]` вместе с
  `base_sha` и меткой времени.
- **`--invariant` — не украшение.** `build` вклеивает `invariants.md` в
  бриф каждой задачи. Если доработка вызвана отсутствующим правилом
  (на vireo язык интерфейса не был записан нигде — поэтому весь UI вышел
  английским), правку кода без правки правила придётся повторять.
  Флаг делает «продолжить проект» и «записать правило» одной транзакцией.
- **`summary`** отдаёт разбивку `epochs`, чтобы прогресс читался как
  «2 из 4 эпохи 2», а не тонул в задачах первого прогона.

Повторный `reopen` на уже открытом плане отказывает — эпоха не
инкрементится дважды.
